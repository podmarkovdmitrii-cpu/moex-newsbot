ЧТО ПОНАДОБИТСЯ
==========================================================================================
  • Аккаунт на github.com (бесплатный). Если его нет: github.com → «Sign up» → почта, пароль, логин → подтвердите почту.
  • Telegram на телефоне или компьютере.
  • Архив moex-newsbot.zip (лежит в папке «Загрузки\moex-github»). Распакуйте его: правый клик → «Извлечь всё…» → «Извлечь».
  • 15–20 минут. Всё делается на сайте github.com в браузере, ничего устанавливать не нужно.
  ВАЖНО: Интерфейс GitHub на английском. Названия кнопок ниже даны так, как они написаны на сайте, в кавычках «…». Путь по кнопкам показан стрелками: «Settings» → «Secrets and variables».

==========================================================================================
ВАРИАНТ А. БОТ УЖЕ УСТАНОВЛЕН — ОБНОВЛЕНИЕ ДО ВЕРСИИ 2
==========================================================================================
  1) Откройте свой репозиторий на github.com, в котором работает новостной бот. Убедитесь, что в нём есть папка newsbot.
  2) Зайдите в папку newsbot → «Add file» → «Upload files».
  3) Откройте распакованную папку newsbot на компьютере, выделите все файлы (Ctrl+A) и перетащите их в окно браузера. Файлы с такими же именами заменятся.
  4) Внизу страницы нажмите зелёную кнопку «Commit changes».
  5) Обнулите память бота, чтобы виртуальный счёт начался заново по новой стратегии:
     «Actions» → слева внизу «Caches» (раздел «Management») → у каждой строки newsbot-state-… нажмите значок корзины.
  • Если кэши не удалить, бот пересчитает счёт с прежней даты старта уже по новым правилам. При этом он может прислать сообщения о «новых» сделках, которых раньше не было.
  6) Запустите бота вручную: «Actions» → слева «Новостной бот (каждые 5 минут)» → справа «Run workflow» → зелёная «Run workflow». Через 1–2 минуты придёт сообщение «🤖 Новостной бот запущен…» с названием стратегии «…(v2)».
  • Файл расписания news-bot.yml и секреты в обновлении не меняются.

ВАРИАНТ Б. УСТАНОВКА С НУЛЯ
==========================================================================================

Шаг 1. Telegram-бот
-------------------
  • Если у вас уже есть бот «Торговый план дня», используйте его: токен и chat id уже лежат в секретах репозитория. Перейдите к шагу 2.
  1) В Telegram найдите @BotFather (с синей галочкой) → «Start» → отправьте /newbot.
  2) Придумайте имя (любое, например «MOEX новости») и логин, который заканчивается на bot (например moex_news_ivan_bot).
  3) BotFather пришлёт токен вида 1234567890:AAH…xyz — это TG_TOKEN. Никому его не пересылайте и не вставляйте в файлы.
  4) Откройте своего нового бота по ссылке из сообщения BotFather и нажмите «Start» (/start). Без этого бот не сможет вам писать.
  5) Узнайте свой chat id: найдите @userinfobot → «Start» → он ответит сообщением, в котором есть «Id: 123456789». Это число — TG_CHAT_ID.

Шаг 2. Репозиторий
------------------
  ВАЖНО: Рекомендуется отдельный ПУБЛИЧНЫЙ репозиторий только для новостного бота. В публичном репозитории минуты GitHub Actions бесплатны без лимита. В приватном бесплатно 2 000 минут в месяц, а бот каждые 5 минут тратит около 4 500–6 000 минут — он остановится примерно через 10 дней (подробнее в разделе «Лимиты»). Токен и chat id хранятся в секретах и в публичном репозитории не видны никому.
  1) github.com → справа вверху «+» → «New repository».
  2) «Repository name»: moex-newsbot. Выберите «Public». Поставьте галочку «Add a README file» (так проще загружать файлы). Нажмите «Create repository».
  • Можно поставить бота и в тот же репозиторий, где работает «Торговый план дня». Тогда учтите лимит минут приватного репозитория (раздел «Лимиты»).

Шаг 3. Загрузка папки newsbot
-----------------------------
  1) На странице репозитория: «Add file» → «Upload files».
  2) Перетащите в окно браузера ПАПКУ newsbot целиком (из распакованного архива), а не отдельные файлы. GitHub сохранит путь newsbot/….
  3) «Commit changes».
  4) Проверьте: на главной странице репозитория появилась папка newsbot, а в ней 8 файлов (bot.js, regime.js, nlp.js, strategy.json, weights.json, reliability.json, divhist.json, README).

Шаг 4. Файл расписания (самый надёжный способ)
----------------------------------------------
  • Папка .github на Windows скрыта, поэтому её легко потерять при перетаскивании. Надёжнее создать файл прямо на сайте.
  1) На главной странице репозитория: «Add file» → «Create new file».
  2) В поле имени файла наберите точно: .github/workflows/news-bot.yml. После каждой косой черты «/» GitHub сам превратит текст в папку — так и должно быть.
  3) Откройте на компьютере файл news-bot.yml из корня архива в Блокноте (правый клик → «Открыть с помощью» → «Блокнот»), выделите всё (Ctrl+A), скопируйте (Ctrl+C) и вставьте в большое поле на GitHub (Ctrl+V).
  4) «Commit changes…» → в окне ещё раз «Commit changes».
  5) Проверьте: в репозитории есть папка .github → workflows → news-bot.yml. Если файл оказался в другом месте — удалите его (значок «…» → «Delete file») и повторите шаг.
  • Текст файла приведён в конце инструкции (Приложение).

Шаг 5. Секреты (токен и chat id)
--------------------------------
     «Settings» (вкладка репозитория справа вверху) → слева «Secrets and variables» → «Actions» → зелёная «New repository secret».
  Name (имя — точно так, заглавными) | Secret (значение)                                | Обязательно?
  -----------------------------------+--------------------------------------------------+-------------
  TG_TOKEN                           | токен от BotFather, например 1234567890:AAH…xyz  | да          
  TG_CHAT_ID                         | ваш Id от @userinfobot, например 123456789       | да          
  TG_NEWS_CHAT_ID                    | id отдельного чата или канала для новостей (см. раздел «Отдельный канал») | нет         
  • Каждый секрет — отдельной кнопкой «New repository secret» → заполнить «Name» и «Secret» → «Add secret».
  • Без пробелов и кавычек. Если ошиблись — нажмите на секрет → «Update secret».
  ВАЖНО: Без TG_TOKEN бот работает в «тихом» режиме: запуск проходит с зелёной галочкой, но в Telegram ничего не приходит. Если всё зелёное, а сообщений нет, проверьте имя секрета.

Шаг 6. Разрешить Actions
------------------------
  1) «Settings» → слева «Actions» → «General».
  2) «Actions permissions»: выберите «Allow all actions and reusable workflows» → «Save».
  3) Вкладка «Actions» вверху. Если GitHub показывает «Workflows aren't being run on this repository» или кнопку «I understand my workflows, go ahead and enable them», нажмите её.
  • Права «Read and write» этому боту не нужны: память он хранит в кэше GitHub, а не в файлах репозитория.

Шаг 7. Первый запуск вручную
----------------------------
  1) «Actions» → слева «Новостной бот (каждые 5 минут)» → справа серая кнопка «Run workflow» → в выпадающем окне зелёная «Run workflow».
  2) Через 5–10 секунд появится строка запуска с жёлтым кружком. Через 1–2 минуты он станет зелёной галочкой ✓.
  3) В Telegram придёт: «🤖 Новостной бот запущен. Виртуальный счёт 100 000 ₽, стратегия «Режимная: импульс + откат + шорт пробоя + новости (v2)»…».
  4) При первом запуске бот только запоминает последние посты каналов (чтобы не прислать старые новости) и открывает виртуальный счёт. Новости начнут приходить со следующих запусков, сделки — когда стратегия даст сигнал (обычно раз в 1–3 недели).
  • Посмотреть, что делал бот: нажмите на запуск → «run» → раскройте шаг «Новости и сделки». Нормальный журнал:
     запуск 1 старт счёта 2026-10-19
     новых постов 0 кластеров 0
     позиций 0 сделок 0 капитал 100000

Шаг 8. Проверка расписания
--------------------------
  • Дальше бот запускается сам: по будням каждые 5 минут с 07:00 до 23:55 МСК, в выходные раз в 3 часа (чтобы не пропустить новости выходных).
  • Через 15–30 минут на вкладке «Actions» должны появиться новые запуски с пометкой «Scheduled». Первый автоматический запуск иногда задерживается на 15–60 минут — это нормально для GitHub.
  • GitHub не гарантирует точное время: запуск «каждые 5 минут» на деле бывает раз в 5–20 минут, в часы пиковой нагрузки — реже.

ОТДЕЛЬНЫЙ КАНАЛ ДЛЯ НОВОСТЕЙ (НЕОБЯЗАТЕЛЬНО)
==========================================================================================
  • Удобно, если сделки приходят в личный чат, а поток новостей — в отдельный канал.
  1) В Telegram: «Новый канал» → название, например «MOEX новости» → тип «Частный».
  2) В канале: «Управление каналом» → «Администраторы» → «Добавить администратора» → найдите своего бота по логину → разрешите «Публикация сообщений» → «Сохранить».
  3) Узнайте id канала. Опубликуйте в канале любое сообщение, затем откройте в браузере адрес (подставьте свой токен вместо ТОКЕН):
     https://api.telegram.org/botТОКЕН/getUpdates
  • В ответе найдите «"chat":{"id":-100…» — число, которое начинается с -100, это id канала. Если ответ пустой — опубликуйте в канале ещё одно сообщение и обновите страницу.
  4) Добавьте секрет TG_NEWS_CHAT_ID с этим числом (вместе с минусом). Сделки останутся в чате TG_CHAT_ID.

ЛИМИТЫ GITHUB ACTIONS (МИНУТЫ)
==========================================================================================
  Тип репозитория                       | Бесплатно в месяц | Хватит ли на каждые 5 минут                     
  --------------------------------------+-------------------+-------------------------------------------------
  Публичный (Public)                    | без лимита        | да                                              
  Приватный (Private), бесплатный тариф | 2 000 минут       | нет: нужно ~4 500–6 000, бот остановится примерно через 10 дней
  • Каждый запуск занимает меньше минуты, но GitHub округляет его вверх до целой минуты. По будням это около 200 запусков в день.
  • Расход видно здесь: аватар справа вверху → «Settings» → «Billing and plans» (в новом интерфейсе — «Billing and licensing») → «Usage».

Если репозиторий должен остаться приватным
------------------------------------------
  • Откройте .github/workflows/news-bot.yml → значок карандаша («Edit this file») → в строке '*/5 4-20 * * 1-5' замените */5 на */15 → «Commit changes». Получится раз в 15 минут, около 1 500–1 800 минут в месяц.
  • Учтите: если в том же приватном репозитории работает «Торговый план дня», он тоже тратит минуты (около 300–500 в месяц). Тогда ставьте */20.

Как сделать репозиторий публичным
---------------------------------
     «Settings» → «General» → в самом низу «Danger Zone» → «Change repository visibility» → «Change visibility» → «Make public» → подтвердите.
  • Видны станут код и журналы запусков. Секреты не видны никому, в том числе в журналах: GitHub заменяет их на ***.
  ВАЖНО: Не делайте публичным репозиторий, в котором лежат личные данные, ваши настоящие сделки или файлы с токенами. Лучше держать новостной бот в отдельном публичном репозитории.

НАСТРОЙКИ
==========================================================================================
  • Все настройки меняются прямо на сайте: откройте файл → значок карандаша («Edit this file») → изменить → «Commit changes».
  Что                                  | Где                                          | Как                                             
  -------------------------------------+----------------------------------------------+-------------------------------------------------
  Стартовый капитал виртуального счёта | news-bot.yml, строка BOT_CAPITAL: '100000'   | любое число без пробелов; после изменения удалите кэши newsbot-state
  Сколько новостей в день              | news-bot.yml, строка NEWS_PER_DAY: '30'      | например '15' — только самые важные             
  Частота запусков                     | news-bot.yml, строки cron                    | см. ниже                                        
  Список каналов                       | newsbot/bot.js, блок CHANNELS в начале файла | добавить строку вида 'логин_канала': ['Название', 'СМИ'],
  Правила стратегии                    | newsbot/strategy.json                        | менять не рекомендуется: правила проверены на истории как единое целое

Как читать расписание (cron)
----------------------------
  • Время в cron — по UTC. Москва = UTC + 3.
  • '*/5 4-20 * * 1-5' = каждые 5 минут, с 04:00 до 20:55 UTC (07:00–23:55 МСК), понедельник–пятница.
  • '7 6-18/3 * * 0,6' = в 7 минут часа, каждые 3 часа с 06:00 до 18:00 UTC (09:07, 12:07, 15:07, 18:07, 21:07 МСК), суббота и воскресенье.
  • Только торговые часы основной сессии (10:00–18:50 МСК): '*/5 7-15 * * 1-5'.

==========================================================================================
ПАМЯТЬ БОТА И НОВЫЙ СТАРТ СЧЁТА
==========================================================================================
  • Бот хранит память (просмотренные посты, кластеры новостей, открытые позиции, дату старта счёта) в кэше GitHub Actions под именем newsbot-state-….
  • Каждый запуск создаёт новую запись кэша. Старые GitHub удаляет сам (лимит — 10 ГБ на репозиторий; бот занимает несколько мегабайт).
  • Начать виртуальный счёт заново: «Actions» → «Caches» → удалить все newsbot-state-… → «Run workflow». Придёт новое «🤖 Новостной бот запущен».
  ВАЖНО: Если бот не запускался больше 7 дней, GitHub удалит кэш. Бот начнёт счёт заново и пришлёт «запущен». Это нормально.

==========================================================================================
ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ
==========================================================================================
  • Где смотреть: «Actions» → запуск с красным ✗ или нужный запуск → «run» → раскройте шаг с ошибкой. Красный ✗ у шага «Новости и сделки» — ошибка бота, у других шагов — ошибка GitHub (обычно проходит сама при следующем запуске).
  Что видно                                        | Причина                                          | Что сделать                                     
  -------------------------------------------------+--------------------------------------------------+-------------------------------------------------
  «Не найден newsbot/bot.js — загрузите папку newsbot» | папка newsbot не загружена или файлы лежат в корне | загрузите папку newsbot целиком (шаг 3)         
  Вкладка Actions пустая, бота нет в списке слева  | файл расписания не в .github/workflows           | повторите шаг 4: имя файла точно .github/workflows/news-bot.yml
  Всё зелёное, но в Telegram ничего                | нет секрета TG_TOKEN или опечатка в имени        | шаг 5; в журнале будет «(без отправки)»         
  В журнале «telegram: 401»                        | неверный токен                                   | скопируйте токен из @BotFather заново → «Update secret»
  В журнале «telegram: 400 … chat not found»       | неверный TG_CHAT_ID или вы не нажали Start у бота | откройте бота → Start; проверьте id через @userinfobot
  В журнале «telegram: 403 … bot was blocked»      | бот заблокирован в Telegram                      | откройте бота → «Перезапустить» / «Разблокировать»
  «telegram: 400» только для новостей              | бот не администратор канала или неверный TG_NEWS_CHAT_ID | раздел «Отдельный канал», id начинается с -100  
  «канал … HTTP 404» или «HTTP 429»                | канал закрыл веб-версию или временно ограничил запросы | ничего: остальные каналы работают; 429 проходит сама
  «свечи … HTTP 5xx», «котировки дня: …»           | временный сбой Мосбиржи                          | ничего: следующий запуск догрузит данные        
  Запуски по расписанию прекратились               | кончились минуты (приватный репозиторий) или репозиторий неактивен 60 дней | раздел «Лимиты»; при неактивности — «Actions» → бот → «Enable workflow»
  Запуски идут реже, чем раз в 5 минут             | нагрузка на GitHub                               | это нормально; в пиковые часы запуски задерживаются
  Пришло «Новостной бот запущен» второй раз        | кэш удалён или истёк (больше 7 дней без запусков) | счёт начат заново; если не нужно — ничего не делайте

Правило 60 дней
---------------
  • В публичном репозитории GitHub отключает запуски по расписанию, если 60 дней в репозитории не было коммитов. За неделю до этого он присылает письмо на почту.
  • Что сделать: раз в 1–2 месяца внесите любое изменение (например, поправьте строку в README → «Commit changes») или после отключения нажмите «Actions» → «Новостной бот» → «Enable workflow».

==========================================================================================
БЕЗОПАСНОСТЬ
==========================================================================================
  • Токен и chat id храните только в «Secrets». Не вставляйте их в файлы репозитория, в news-bot.yml и в сообщения.
  • Если токен случайно попал в файл или чат: @BotFather → /mybots → ваш бот → «API Token» → «Revoke current token». Получите новый и обновите секрет TG_TOKEN.
  • Бот только читает открытые Telegram-каналы и данные Мосбиржи. Он не подключается к брокерскому счёту и не совершает реальных сделок: счёт виртуальный.
  • Торговля на инсайдерской информации запрещена законом (224-ФЗ). Бот использует только публичные источники; «ранние» новости — это сообщения СМИ со ссылкой на источники, они могут не подтвердиться.
  • Сообщения бота — исторически проверенная модель на виртуальном счёте, а не инвестиционная рекомендация.

==========================================================================================
ПРИЛОЖЕНИЕ. ТЕКСТ ФАЙЛА .github/workflows/news-bot.yml
==========================================================================================
name: Новостной бот (каждые 5 минут)

on:
  schedule:
    - cron: '*/5 4-20 * * 1-5'    # будни 07:00–23:55 МСК (время в cron — UTC)
    - cron: '7 6-18/3 * * 0,6'    # выходные: новости раз в 3 часа
  workflow_dispatch:

concurrency:
  group: newsbot
  cancel-in-progress: false

jobs:
  run:
    runs-on: ubuntu-latest
    timeout-minutes: 8
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - name: Восстановить состояние бота
        uses: actions/cache/restore@v4
        with:
          path: newsbot-state
          key: newsbot-state-${{ github.run_id }}
          restore-keys: newsbot-state-
      - name: Новости и сделки
        env:
          TG_TOKEN: ${{ secrets.TG_TOKEN }}
          TG_CHAT_ID: ${{ secrets.TG_CHAT_ID }}
          TG_NEWS_CHAT_ID: ${{ secrets.TG_NEWS_CHAT_ID }}
          STATE_DIR: ${{ github.workspace }}/newsbot-state
          BOT_CAPITAL: '100000'
          NEWS_PER_DAY: '30'
        run: |
          BOT=$(find . -name bot.js -path '*newsbot*' | head -1)
          if [ -z "$BOT" ]; then echo "Не найден newsbot/bot.js — загрузите папку newsbot в репозиторий"; exit 1; fi
          node "$BOT"
      - name: Сохранить состояние бота
        if: always()
        uses: actions/cache/save@v4
        with:
          path: newsbot-state
          key: newsbot-state-${{ github.run_id }}
